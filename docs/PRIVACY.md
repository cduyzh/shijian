# 本地保存与隐私说明

食间以私人使用为目标，菜单通过浏览器 `localStorage` 保存，不通过 GitHub 保存，也不提供账号间或设备间的菜单同步。

## 保存在哪里

浏览器将计划保存到当前网页来源下。来源由协议、域名和端口共同决定：例如在 `http://localhost:4173` 创建的计划，不会自动出现在另一个端口、另一个浏览器或另一台设备中。

本地记录使用 `shijian:v1` 键，包含周期日期、每天选定的午餐、晚餐、水果、菜谱收藏、食材准备/库存标记和实际采购合计。菜谱与食材参考数据随应用提供。应用不需要用户填写身体指标、病历或个人身份信息来安排菜单。同一来源的其他标签页会读取更新后的记录；这不构成跨设备同步。

未完成的当前草稿另外使用 `shijian:draft:v1` 保存，包含开始日期、逐餐已选菜品、主动选择的水果、当前编辑日及关联正式计划。未选内容保留为空；推荐功能不会自动填写水果。这个键用于恢复当前草稿，不改变正式菜单的原有 `shijian:v1` 结构，也不构成后台上传或跨设备同步。

## 保存并不等于备份

- 清理站点数据、浏览器重置、卸载浏览器或设备损坏，可能删除计划。
- 无痕窗口中的记录可能在窗口关闭后消失。
- 更换浏览器、设备、域名或端口，不会自动迁移记录。
- 共享设备上的其他使用者可能查看同一浏览器中的菜单。

可在“本地数据与设置”中导出已保存正式菜单的 JSON 备份，当前导出不包含未完成草稿。需要迁移时，在另一浏览器或网址下手动导入；应用会检查格式，再提示确认替换当前本机正式记录。导入不是合并，备份文件也可能包含实际采购合计等私人信息，建议自行妥善保存。当前本地保存不承诺云端备份或自动跨设备恢复。

若旧记录无法读取，保存新内容前会把原始文本另存为 `shijian:v1:recovery`；设置中可下载原始恢复副本。清空本机数据时也会移除恢复副本。

## 删除记录

可在“我的菜单”中删除指定计划，确认后同步删除该计划的食材准备标记、库存标记和实际采购合计。也可在“本地数据与设置”中确认清空所有本机记录，或在浏览器站点设置中清除本地存储。清空会影响该来源下的全部计划、收藏、当前草稿及恢复副本；只能依赖使用者自行保留的正式菜单备份恢复，GitHub 不保存这些记录。

## 访问与源码边界

`localStorage` 不是数据库权限系统，没有登录验证或访问控制功能。当前通过 Sites 提供拥有者私人访问，使用 ChatGPT 登录；菜单本身继续由浏览器本地保存。若调整托管地址或访问对象，应同时核对平台访问设置。

静态网页由浏览器加载 HTML、CSS、JavaScript 和图片，因此有权访问网页的使用者能够查看这些资源。公开仓库排除应用源码，不能阻止浏览器查看已提供的网页文件。

本仓库只公开说明文档，禁止上传菜单导出、浏览器存储、访问凭据、个人截图或其他私人数据。生成图片属于应用资产，也不在本仓库公开范围内。

餐盘和熟菜图像由 AI 根据配方与公开烹饪资料生成，用于成品效果示意，并非用户的私人餐桌实拍。点击食材、查看做法或切换成品/食材图片在当前应用界面内完成，不需要上传个人照片。

## 后续变化

如果以后加入账号、云同步、第三方统计或在线服务，应先更新本说明，明确传输的数据、用途、保存期限和删除方式。当前说明不替代托管平台或外部服务各自的隐私政策。
