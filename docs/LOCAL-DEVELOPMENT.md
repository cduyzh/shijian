# 本地开发与预览

食间采用无需构建的静态网页结构。本地应用文件位于开发者工作区的 `dist/`，通过普通 HTTP 静态服务打开。

私人仓库已包含 `dist/` 与应用运行资产。持有仓库权限的维护者克隆后即可按下方说明启动；不需要后端或构建步骤。

## 本地文件结构

```text
食间/
├── README.md
├── .gitignore
├── docs/
│   ├── PRODUCT.md
│   ├── PRIVACY.md
│   ├── LOCAL-DEVELOPMENT.md
│   ├── NUTRITION-SOURCES.md
│   ├── visual-assets.md
│   └── COOKED-REFERENCES.md
└── dist/                   # 本地应用，不提交
    ├── index.html
    ├── app.js
    ├── styles.css
    ├── data.js
    ├── nutrition.js        # 按双人原料与餐次统一计算
    ├── visuals.js
    ├── meal-scene.js       # WebGL 几何餐盘及资源生命周期
    ├── vendor/             # 本地 Three.js 与许可证
    ├── asset-layout.js
    └── assets/             # 本地图片与图标，不提交
```

## 启动本地预览

需要本机已安装 Python 3。在完整工作区中运行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

然后打开 `http://localhost:4173`。绑定到 `127.0.0.1` 可将此预览服务限制在本机。结束时在终端按 `Ctrl+C` 停止服务。

建议通过 HTTP 预览，不直接双击 HTML 文件。菜单按浏览器来源保存，修改端口或改用 `127.0.0.1` 作为网址会产生不同的本地存储空间。

## 修改与自查

修改应用时保留当前计划，检查新旧数据是否仍可读取。基础检查应覆盖首次使用、生成 3–7 天菜单、切换日期、替换菜品、未来周期、历史计划和刷新后恢复。采购分类与参考预算应跟随选定菜单及餐次更新。

餐次相关检查应覆盖全局默认偏好、单个周期的 `mealMode`、草稿内两种模式切换、仅晚餐保存与导入、旧版未设置模式的历史计划。改默认值不应改写历史周期；仅晚餐模式的选菜进度、采购和营养汇总均不应计入午餐，水果仍由用户主动选择。

营养算例应使用统一 `nutrition.js`：菜谱按 `servings` 缩放到双人配方，双人合计除以 2 得到每人均分参考，水果采用每人 200 g 可食部的内部模型量。详情克重表需明确双人原料／每人均分及干品口径，营养数值不能被表述为实际全天摄入。

WebGL 检查需确认实际 WebGL2 context、食物 mesh 与实例渲染，拖动和键盘转动、复位、菜区点击，反复换日和离开页面后释放 renderer，并保证静止画面不会持续申请动画帧。设备不支持 WebGL 时应显示可点击的成品照片。素材归一化只读取透明 alpha 边界，再用保持比例的 SVG 显示窗口等比缩放和居中，不能把不同品种合并或裁掉主体。

界面检查聚焦本次修改，在桌面与手机宽度确认布局，并检查减少动态效果设置。核对单菜卡片不叠装饰餐盘、菜单与搜索不重复全页淡入、成品／食材切换保持详情容器、从详情返回恢复列表位置，以及页面不显示独立的制作时长标签。浏览器验收遵守工作区 `AGENTS.md` 的资源管理规则，复用同一轮浏览器，结束时清理本轮创建的资源。

本文列出维护检查范围，不表示上述检查已在任何指定版本完成。实际交付应以当次验收记录为准。

## 提交到私人 GitHub 仓库

仓库可见性为 PRIVATE，提交前仍要检查 `git status --short` 和 `git diff --cached --name-only`。允许提交静态应用代码、运行图片、依赖许可证与文档；`.gitignore` 排除菜单导出、浏览器数据、凭据、`.openai/` 托管身份、`.site-source/`、`.qa/` 以及历史生成原图。不要使用 `git add -f` 绕过排除规则。

GitHub 提交与网站部署分别记录。本仓库没有配置 GitHub Pages，推送源码不会自动更新线上应用。
